# Top features: findings

Generated by `python -m src.top_features` from SHAP, permutation importance, Decision Tree importance and Logistic Regression coefficients (`outputs/explainability/feature_importance.csv`).

1. **`execution_time_s` is the strongest flaky-test signal.** It ranks SHAP #1, Permutation #1, Decision Tree #1, LR coefficient #1. In SHAP, a higher value pushes the flaky score up.
2. **6 features are in the top 10 of at least 3 of the 4 methods:** `execution_time_s`, `source_classes_covered`, `source_lines_covered`, `changed_line_churn_w100`, `covered_lines`, `smell_fire_and_forget`. These are the features we can trust most, because models that work very differently all point to them.
3. **Coverage matters: tests that touch more of the project are riskier.** The best coverage feature, `source_classes_covered`, is #2 overall (SHAP #2, Permutation #2, Decision Tree #3, LR coefficient #3); in SHAP, a higher value pushes the flaky score up. Tests that exercise many classes depend on more shared state, which is a classic cause of flakiness.
4. **Code churn matters, but the 8 churn windows share the credit.** 6 of the 8 windows reach the overall top 10; the strongest is `changed_line_churn_w100` (#4). Only `changed_line_churn_w100` is in the top 10 of all 4 methods: the windows are strongly correlated, so each method picks different windows.
5. **Test smells are weak signals on their own.** The best smell, `smell_fire_and_forget`, is only #12 overall (SHAP #9, Permutation #21, Decision Tree #9, LR coefficient #7, top 10 in 3 of 4 methods); 4 of the 8 smells are not in any method's top 10. Smells are rare (most appear in under 10% of tests), so they help explain some flaky tests but cannot separate most of them.
6. **The methods disagree most on `changed_line_churn_w5`** (SHAP #17, Permutation #7, Decision Tree #23, LR coefficient #4). Logistic Regression only sees straight-line effects of each feature, while the trees can use a feature only in some branches, so features with uneven effects get very different ranks.
7. **The methods agree at the top but less further down.** The closest pair is SHAP and Permutation (Spearman 0.79); the least similar is Decision Tree and LR coefficient (0.32).
8. **Power BI Key Influencers is not included yet.** Fill in `outputs/powerbi/key_influencers_top.csv` and rerun this script to add it as a 5th view.
